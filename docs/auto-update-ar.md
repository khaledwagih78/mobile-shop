# التحديث التلقائي لنسخة الديسكتوب (exe)

البرنامج المثبّت (Setup) بقى **يحدّث نفسه تلقائياً** من GitHub Releases:
يفحص عند التشغيل + كل 4 ساعات، ينزّل التحديث في الخلفية، وبعدين يسأل العميل
"إعادة التشغيل الآن؟" لتثبيته.

> ⚠️ **النسخة المثبّتة (Setup/nsis) بس** هي اللي بتحدّث نفسها.
> نسخة الـ **portable** لا تحدّث نفسها (قيد في electron-updater).
> الريبو **public** فالعميل مش محتاج أي توكن.

---

## كيف تُصدِر نسخة جديدة (خطوة بخطوة)

### 1) ارفع رقم الإصدار
في `package.json` غيّر `version` (لازم يكبر كل مرة):
```json
"version": "1.0.1"
```

### 2) جهّز توكن GitHub (مرة واحدة)
التوكن ده **لك أنت** (لرفع النسخة) — مش بيتوزّع للعملاء:
- GitHub → Settings → Developer settings → **Personal access tokens** → Generate
- صلاحية: **repo** (أو Contents: Read/Write)
- في PowerShell قبل النشر:
```powershell
$env:GH_TOKEN = "ghp_xxxxxxxxxxxx"
```

### 3) ابنِ وانشر
```powershell
npm run electron:publish
```
ده بيبني النسخة ويرفع للـ GitHub Releases:
- ملف التثبيت (Setup .exe)
- ملف `latest.yml` (اللي البرنامج يقرا منه التحديثات)
كـ **Draft Release**.

### 4) انشر الـ Release
افتح GitHub → **Releases** → افتح الـ draft → **Publish release**.
بمجرد نشره، كل العملاء على النسخة المثبّتة هيوصلهم التحديث تلقائياً.

---

## اللي العميل بيشوفه
1. يفتح البرنامج عادي → التحديث بينزّل في الخلفية (من غير إزعاج).
2. أول ما يخلص: رسالة **"تحديث جديد جاهز — إعادة التشغيل الآن / لاحقاً"**.
3. لو اختار "لاحقاً" → بيتثبّت تلقائياً عند أول إقفال للبرنامج.

---

## ملاحظات
- **بيانات العميل آمنة**: التحديث بيغيّر البرنامج بس، مش قاعدة البيانات المحلية.
- **رقم الإصدار**: لازم يزيد كل نسخة وإلا مش هيعتبرها تحديث.
- **النسخة المثبّتة فقط**: وزّع ملف الـ **Setup** للعملاء (مش الـ portable) عشان ياخدوا التحديثات.
- **زرار تحقق يدوي** (اختياري): فيه IPC اسمه `app:check-updates` تقدر تربطه بزرار "تحقق من التحديثات" في الإعدادات لاحقاً.
